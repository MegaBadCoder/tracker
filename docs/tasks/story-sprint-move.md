# Перенос истории вместе с задачами в спринт

**Status:** done
**Branch:** feat/agile-board
**Worktree:** /Users/v/projects/Alfy/.worktrees/feat-agile-board
**Goal:** В тестовом Agile-проекте пользователь переносит историю из бэклога в спринт через меню или drag-and-drop; история и её задачи сохраняют новое назначение после перезагрузки, включая пустую историю.
**Mode:** hands-off

## Context
- Истории группируются по Task.sprintId; BoardGroup не хранит спринт, SprintBlock перетаскивает только задачи.
- Worktree feat/agile-board чистый на df9012b, имеет собственные node_modules и тестовую SQLite-базу; UI localhost:5173, API localhost:3102, Dev 424242.

## Design
Сохранять nullable BoardGroup.sprintId для истории. PATCH /projects/:projectId/groups/:id/sprint с обязательным sprintId (UUID либо null) атомарно переносит историю и все её задачи вне закрытых спринтов. Выполненные задачи незакрытых спринтов тоже переносятся: пользователь выбирает всю группу. Эпики не назначаются. Пустая история появляется в назначенном блоке. Старые истории получают null, их задачи сохраняют назначения и прежнюю группировку. Новая задача наследует спринт истории лишь при отсутствии явного sprintId; явный null имеет приоритет. Завершение спринта переносит открытые истории, выполненные сохраняет; удаление очищает FK без удаления историй и задач.
Альтернатива переноса циклом PATCH задач проще по схеме, но неатомарна и не переносит пустую историю; выбран серверный контракт по образцу релизов (GPC4, GPC5, GPC8). UI предлагает меню и отдельную группу drag историй, независимую от drag задач. Фильтры не ограничивают серверный состав переноса.
TDD: yes.

### Invariants
- IV1 — История и спринт принадлежат одному доступному пользователю Agile-проекту; закрытый спринт, эпик и некорректный DTO отвергаются.
- IV2 — Назначение истории и всех переносимых задач атомарно, задачи закрытых спринтов и других историй сохраняются; задачи спринта имеют колонку.
- IV3 — Пустая история сохраняет назначение; наследование допускается только без явного sprintId.
- IV4 — Завершение и удаление спринта сохраняют данные и корректно переносят/очищают назначения историй.
- IV5 — Меню и drag вызывают один контракт, данные перечитываются с сервера; при ошибке пользователь видит сообщение, фильтры не ограничивают перенос.
